## 7 ноября — массивы и кортежи в `Localization`

В `content.tsx` тип `articles: [{ ... }]` требует ровно одну статью, а `content: [{ ... }]` — ровно один раздел. Квадратные скобки вокруг типа задают кортеж с фиксированными позициями. Чтобы поддержать произвольное число статей и разделов, используй `articles: { title: string; content: { paragraph: string; text: string }[] }[]`. Скобки после типа элемента задают массив. Ошибка TS2322 возникла потому, что в данных две статьи, а тип допускает одну. Исправление нужно применить на обоих уровнях.

### Что важно вспомнить

- **Props** — данные и функции от родителя; **state** — память компонента между рендерами. Событие вызывает переданную функцию, родитель обновляет state, новое значение приходит вниз при следующем рендере.
- `useState` возвращает значение и функцию обновления. В классах похожую задачу решает `this.setState`; это другой API.
- `useState<'light' | 'dark'>('light')`: в угловых скобках — допустимые типы значений, в круглых — начальное значение.
- В `setTheme(previous => ...)` параметр `previous` получает значение от React; имя выбираем сами. Функция возвращает новое состояние.
- `setTheme` устанавливает значение и требует аргумент; `toggleTheme` сам вычисляет переключение и вызывается без аргументов. Поэтому кнопке передаём `toggleTheme`.
- `unknown` требует проверить внешние данные перед использованием. Тип TypeScript сам по себе ответ сервера не проверяет.
- `...` раскрывает элементы/свойства (spread) либо собирает оставшиеся значения (rest). Копирование через spread поверхностное.
- **Лог сразу после setter показывает состояние текущего рендера.** Поэтому `console.log(theme)` после `setTheme(...)` и `console.log(lang)` после `setLang(...)` сейчас выводят прежнее значение. Это не доказательство, что обновление не сработало. Надёжнее показать состояние в интерфейсе.

## Ошибка типов при передаче обработчика темы

В App передан `onToggleTheme={setTheme}`, но Header ожидает `onToggleTheme: () => void`. Это разные контракты: Header сообщает о клике без аргументов, а `setTheme` требует новое значение темы или функцию вычисления значения. Исправление для самостоятельного внесения: `onToggleTheme={toggleTheme}`. Функция toggleTheme уже есть в App и вызывает `setTheme(previous => previous === 'light' ? 'dark' : 'light')`.

Для языка `onToggleLang={setLang}` совместим с текущим prop `(value: string) => void`, поскольку список передаёт конкретную строку. Для темы кнопка сообщает намерение «переключить», а не выбранное значение. Передача обработчика записывается без вызова: `{toggleTheme}`, не `{toggleTheme()}`.

После исправления обработчика выбранная тема ещё должна быть связана с оформлением, например через `data-theme={theme}` на обёртке и CSS. Само обновление состояния цвета не меняет.

## Выбор языка: состояние и обработчики

Текущий разбор: язык хранится в App, Header получает текущее значение и функцию изменения через props. Для выбора нескольких вариантов подходит стандартный `<select>` с `<option>`. Он сам открывает список; вручную вставлять элементы в DOM не нужно. `HeaderActionButton` остаётся обычной кнопкой.

Сигнатура `() => 'ENG' | 'RU'` описывает функцию без аргументов, которая возвращает язык. Для сообщения о выборе нужна другая сигнатура: `(language: 'ENG' | 'RU') => void` — функция принимает язык и ничего полезного не возвращает.

В App нужно передать Header `lang={lang}`, `onChangeLang={changeLang}`, `onToggleTheme={toggleTheme}`. Сейчас в прочитанном коде Header вызывается без обязательных props. `tohhleLang` стоит переименовать в `changeLang`, поскольку функция устанавливает выбранный язык, а не переключает его на следующий.

У select использовать `value={props.lang}` и `onChange`. Из `event.currentTarget.value` приходит строка: проверить `value === 'ENG' || value === 'RU'`, затем вызвать `props.onChangeLang(value)`. Проверка позволяет TypeScript сузить тип без принудительного приведения.

Поток: App передаёт значение вниз; пользователь выбирает option; обработчик Header вызывает переданную функцию с выбранным ключом; App обновляет состояние; новое значение снова приходит в Header. Дублировать выбранный язык в локальном состоянии Header не нужно. Смена ключа языка сама по себе не переводит интерфейс: словарь переводов добавляется отдельным шагом.

Статус: объяснение подготовлено по текущим исходникам, реализация выбора языка ещё не проверена. Тема объявлена в App, но пока не передана в Header и не связана с оформлением страницы.

## 2026-10-30 — Макет и Flexbox

### Желаемое расположение

### Что есть в коде

Файл: `first-big-learning-project/src/App.css`.

```css
.main-content-container {
  display: flex;
  flex-direction: row;
}

.side-panel-container {
  width: 20%;
}
```

`display: flex` управляет расположением непосредственных дочерних элементов. `flex-direction: row` размещает их в строку; это значение используется по умолчанию.

Боковым панелям задана ширина по 20% от ширины контейнера. Это исходный размер: при нехватке места flex-элементы по умолчанию могут сжиматься.

Центральному блоку не задан рост, поэтому он не обязан занимать всё свободное место. Свободное пространство может оставаться справа: по умолчанию элементы располагаются от начала строки.

### Предложенное изменение

```css
.content-container {
  flex: 1;
  min-width: 0;
}
```

- `flex: 1` позволяет центральному блоку расти и занимать оставшееся пространство. Это сокращение обычно разворачивается браузером в `flex: 1 1 0%`.
- `min-width: 0` разрешает блоку сжиматься меньше минимальной ширины его содержимого. Например, длинная строка иначе может мешать сжатию. Само по себе это свойство не переносит длинные слова.

Статус на 2026-10-30: `flex: 1` добавлен в файл; пользователь подтвердил, что расположение стало нормальным. `min-width: 0` пока не добавлен. Отображение в браузере ассистентом не проверено.

### Как отличить узкий контейнер от незаполненного контейнера

Временно добавить:

```css
.main-content-container {
  outline: 2px solid red;
}

.main-content-container > * {
  outline: 1px solid blue;
}
```

Красная рамка показывает границу контейнера, синие — границы его непосредственных детей. `outline` не занимает место в раскладке.

Если красная рамка занимает доступную ширину, а синие блоки сгруппированы слева, проверяем распределение свободного пространства между детьми.

Если сама красная рамка занимает только половину страницы, проверяем родителей: `#root`, `body`, `html`. В инструментах разработчика смотрим фактическую ширину и применённые правила `width`, `max-width`, `display`. В прочитанных файлах причина такого ограничения не найдена; утверждать её без проверки браузера нельзя.

После проверки временные рамки убрать.

### Полезные различия

- `text-align: center` выравнивает текст и строчное содержимое внутри блока. Оно не центрирует сам блок и не распределяет flex-колонки.
- `justify-content` распределяет элементы и свободное место вдоль главной оси Flexbox. При `row` это горизонтальная ось.
- `align-items` выравнивает элементы поперёк главной оси. При `row` это вертикальная ось.
- Порядок элементов в JSX определяет их обычный порядок отображения. Сейчас первая панель подписана `Right-panel`, но находится слева.

7. Проверить успешную загрузку, повторный запрос и ошибку сети. После этого отдельно разобрать автоматическую загрузку при открытии страницы через `useEffect` и отмену запроса при очистке эффекта.

### Что важно понять

- `useState<string[]>([])` означает состояние с массивом строк. Без указания типа пустой массив в этом случае может получить слишком узкий тип `never[]`.
- `fetch` получает HTTP-ответ; `response.json()` читает его тело. Оба шага асинхронные.
- Обновление состояния вызывает новый рендер, и JSX показывает полученные данные.
- Тип TypeScript описывает ожидания, но не проверяет ответ сервера во время выполнения. Для внешних данных нужна проверка структуры.
- Текст выводим как `{content}` внутри JSX; для обычного текста HTML-вставка не нужна.
- Сейчас свойство заголовка в `Article` называется `hedaer` с опечаткой. При переименовании в `header` нужно обновить интерфейс, компонент и все места его использования.

### Разбор `useState` и `unknown`

```tsx
const [paragraphs, setParagraphs] = useState<string[]>([])
```

`paragraphs` — значение состояния для текущего рендера; `setParagraphs` — функция обновления; `string[]` — тип массива строк; `[]` — начальное значение. React сохраняет состояние между рендерами. Вызов функции обновления запрашивает обновление состояния и новый рендер. Переменная из уже выполняющегося обработчика при этом не меняется: новое значение будет доступно при следующем рендере.

В `const received: unknown = data.paragraphs` тип `unknown` означает, что структуру значения ещё нужно установить. Он сам не выполняет проверку: её делают `Array.isArray` и `typeof`. После проверки массива и всех его элементов TypeScript позволяет использовать значение как массив строк.

Проверка понимания: если заменить `setParagraphs(received)` на `console.log(received)`, ответ будет получен и выведен в консоль, но состояние `paragraphs` не обновится. Поэтому при изначально пустом массиве статьи не появятся; если статьи уже были, они останутся прежними. Другие вызовы обновления состояния, например `setIsLoading(false)`, всё ещё могут вызвать рендер, но новых абзацев в состоянии не будет.

Вывод в консоли не исчезает автоматически при завершении функции. Он обычно остаётся до очистки консоли или перезагрузки страницы; сохранение при переходах зависит от настроек инструментов разработчика. Локальная переменная доступна только в своей области видимости; освобождение памяти происходит, когда данные больше не нужны и на них нет сохраняемых ссылок. Консоль также может удерживать ссылки на выведенные объекты.

Пользователь верно определил, что один `console.log` не обновляет состояние и не выводит статьи на страницу.

### Тип темы и параметр `previous`

```tsx
const [theme, setTheme] = useState<'light' | 'dark'>('light')
```

Угловые скобки передают аргумент типа функции `useState`. `'light'` и `'dark'` в позиции типа — строковые литеральные типы, каждый допускает только одно точное значение. Символ `|` объединяет типы: допустимо одно из двух значений. Поэтому `setTheme('dark')` допустим, а `setTheme('blue')` вызывает ошибку TypeScript. Круглые скобки передают начальное значение состояния — `'light'`. TypeScript проверяет типы при разработке; запись типа сама не является проверкой данных во время выполнения.

```tsx
setTheme(previous => previous === 'light' ? 'dark' : 'light')
```

`previous` — параметр стрелочной функции, имя выбираем сами. React вызывает переданную функцию обновления и передаёт ей предыдущее состояние с учётом более ранних обновлений в очереди. Возвращённое значение становится новым состоянием. Развёрнутый вариант:

```tsx
setTheme((previous) => {
  if (previous === 'light') {
    return 'dark'
  }
  return 'light'
})
```

Функция обновления должна быть чистой: вычислять результат без запросов, изменения внешних данных и других побочных действий. Функциональная форма полезна, когда новое значение зависит от предыдущего; для установки заранее известного значения достаточно `setTheme('dark')`.

### Три точки `...`: spread и rest

В реальном коде `...` имеет два связанных применения, зависящих от места записи.

**Spread — раскрытие значений:**

```js
const numbers = [1, 2]
const extended = [...numbers, 3] // [1, 2, 3]
const nested = [numbers, 3] // [[1, 2], 3]

const user = { name: 'Alex', age: 25 }
const updated = { ...user, age: 26 } // { name: 'Alex', age: 26 }

Math.max(...numbers) // аналогично Math.max(1, 2)
```

В массиве и аргументах функции spread раскрывает элементы итерируемого значения (например, массива). В объекте он копирует собственные перечисляемые свойства. В объекте при совпадении ключей побеждает значение, записанное позже: `{ ...user, age: 26 }` меняет возраст, а `{ age: 26, ...user }` восстановит возраст из user.

Практика для React:

```tsx
setParagraphs(previous => [...previous, 'Новый абзац'])
setForm(previous => ({ ...previous, name: 'Анна' }))
```

Создаются новые массив или объект; исходные не изменяются. Круглые скобки вокруг объекта в краткой стрелочной функции нужны, чтобы `{}` воспринимались как возвращаемый объект, а не тело функции.

Копирование поверхностное: вложенные объекты и массивы сохраняют ссылки. Например, после `const copy = { ...user }` вложенное поле `copy.settings` будет тем же объектом, что и `user.settings`, если такое поле есть. Для изменения вложенного состояния нужно копировать каждый изменяемый уровень.

**Rest — сбор оставшихся значений:**

```js
const [first, ...others] = [10, 20, 30]
// first === 10, others — [20, 30]

function sum(...values) {
  return values.reduce((total, value) => total + value, 0)
}
sum(1, 2, 3) // 6; внутри values — [1, 2, 3]
```

В параметрах функции rest собирает аргументы в массив; при деструктуризации собирает оставшиеся элементы или свойства. Rest-элемент должен быть последним. Удобная памятка: spread раскрывает, rest собирает. Это синтаксис JavaScript, а не особенность React.
